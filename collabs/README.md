# Collab Room — планировщик коллабораций

**Версия 1.0 (MVP).** Отдельный проект в папке `collabs/` репозитория `Gilbertum/streamerskaya`. Корневой сайт `streamerskaya` не меняется.

Предполагаемый адрес GitHub Pages (если Pages публикует ветку main, корень /root):
**https://gilbertum.github.io/streamerskaya/collabs/**

## Что работает

- Вход по email/паролю через Firebase Authentication. **Публичной регистрации нет.**
- Допуск по `allowedUsers/{UID}`: только одобренные участницы видят закрытые данные.
- Личные профили: ник, Twitch, Steam, обычные часы по будням и выходным.
- Календарь: стрим, «не могу», «под вопросом», «точно свободна». Без отметки день/время считается свободным. Для блокировки **целого дня** в форме события есть кнопка **«Отметить весь день (00:00–00:00)»**.
- События `20:00–02:00` правильно блокируют вечер и следующий день до 02:00.
- Поиск свободных участниц по игре, дате и часам МСК; кандидаты сортируются на свободных / под вопросом / занятых.
- Приглашения: предложить → принять/отклонить → при принятии блокируется окно **у обеих**. Участницы могут отменить уже принятый коллаб.
- Живые обновления календаря и предложений при открытом сайте.
- Персональные зрительские ссылки `#/s/UID`: **только отмеченные как публичные стримы**, без внутренних расписаний, статусов и переписки.

## Firebase: полная инструкция для владельца (без программирования)

### 1. Создать проект

1. Откройте **https://console.firebase.google.com/** и войдите в Google-аккаунт владельца.
2. Нажмите **Create a project / Создать проект**. Например, `xwaran-collab-room`.
3. Google Analytics для этой маленькой программы можно **отключить**.
4. В настройках проекта **Project settings / Настройки проекта** найдите **Your apps / Ваши приложения**, нажмите значок **Web (</>)** и зарегистрируйте приложение `Collab Room`.
5. Скопируйте объект `firebaseConfig`: `apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId`. Это публичная конфигурация веб-приложения, **не секретный пароль**.

### 2. Подключить Firebase Authentication

1. В меню Firebase откройте **Authentication** (в некоторых версиях интерфейса: **Build / Authentication**, либо **Security / Authentication**).
2. Нажмите **Get started / Начать**.
3. Вкладка **Sign-in method / Способы входа** → **Email/Password** → **Enable / Включить** → Save.
4. Проверьте **Settings / Настройки → Authorized domains / Авторизованные домены**. Добавьте `gilbertum.github.io`, если его там нет. Вводите домен **без** `https://`, без слэша и без `/streamerskaya/collabs/`.

### 3. Создать Cloud Firestore (не Realtime Database)

1. Firebase → **Firestore Database** → **Create database / Создать базу данных**.
2. Выберите **Standard edition** и **Native mode**, если консоль спрашивает; используйте основную базу `(default)`.
3. Выберите регион. Желательно европейский, доступный вашему проекту; впоследствии перенос региона потребует миграции.
4. Выберите **Start in production mode / Рабочий режим** (закрытые правила по умолчанию).
5. Откройте вкладку **Rules / Правила**.
6. Откройте на GitHub файл **`collabs/firestore.rules`**, скопируйте **весь** текст от `rules_version = '2';` до последней `}`.
7. Замените им содержимое редактора в Firebase → **Publish / Опубликовать**. Без этого шага сайт не сможет читать и записывать данные.

**Важно:** не используйте правила `allow read, write: if true;` и не выбирайте тестовый режим на постоянной основе. Публичные ссылки работают через отдельную коллекцию `publicSchedules`, а не через открытие всей базы.

### 4. Внести настройки Firebase в опубликованный сайт

1. Откройте **https://github.com/Gilbertum/streamerskaya/blob/main/collabs/firebase-config.js**.
2. Нажмите значок карандаша **Edit this file** (при необходимости: `...` → `Edit file`).
3. Внутри `export const firebaseConfig = { ... }` замените **все** шаблонные значения `PASTE_...` значениями объекта, который Firebase дал на шаге 1. Не удаляйте `export const firebaseConfig =`.
4. Нажмите **Commit changes** → сохраните в основную ветку `main`. Можно через отдельную ветку + Pull Request, если хочется оставить историю релизов.
5. Откройте сайт через несколько минут и обновите страницу с зажатой клавишей Ctrl (Ctrl+F5). Вместо «Firebase ещё не подключён» появится форма входа.

**Никогда не вставляйте** в этот файл сервисный ключ `private_key`, JSON из **Service accounts**, пароли, токены Twitch и ключи админ-доступа. `firebaseConfig` из настройки Web app, наоборот, рассчитан на использование в браузере.

### 5. Добавить аккаунты для каждой стримерши

Самый простой приватный способ — создать аккаунты **вручную**, без формы открытой регистрации.

Для **каждой** участницы, включая себя:

1. Firebase → **Authentication → Users / Пользователи** → **Add user / Добавить пользователя**.
2. Укажите её **email** и длинный случайный временный пароль. Не публикуйте пароль. Пользователь сможет установить свой через восстановление.
3. После создания скопируйте поле **UID** (длинный уникальный идентификатор пользователя).
4. Firebase → **Firestore Database → Data / Данные** → **Start collection / Создать коллекцию**.
   - Collection ID: `allowedUsers` (строго такое написание).
   - Document ID: вставьте **UID** из Authentication (не ник и не email).
   - Поле: **`enabled`**, тип **boolean**, значение **true** (именно логическое true, не строка `"true"`).
   - Сохраните.
5. Следующую участницу добавляйте в **ту же** коллекцию `allowedUsers` через **Add document**, каждый раз с её собственным UID.

**Как впервые войти участнице:** откройте сайт, введите **свою почту** в форме входа, нажмите **Восстановить пароль**, затем перейдите по письму Firebase и установите свой собственный пароль. После этого войдите на сайт с новым паролем.

**Если на экране «Аккаунт ещё не допущен»**, означает, что Authentication работает, но в Firestore нет документа `allowedUsers/{UID}` с `enabled = true`. UID будет написан на экране: сверьте его с Firestore.

### 6. Настроить профиль и дать ссылку своему чату

1. После входа откройте **Профиль**.
2. Заполните ник, Twitch, Steam, желаемые часы стримов по будням / выходным (МСК).
3. Нажмите **Сохранить профиль**.
4. На экране профиля скопируйте индивидуальную ссылку **«Ссылка для зрителей»**.
5. В **Расписание → + Добавить событие** укажите тип **Стрим**, игру, дату и часы, поставьте галочку **Показать зрителям**.
6. Сохраните и проверьте ссылку в браузере **инкогнито**: должны быть видны только публичные стримы. Типы «не могу», «под вопросом», приглашения и другие участницы не должны отображаться.

### 7. Проверить коллабы от начала до конца

Понадобятся две разные учётные записи из разрешённого списка, например Xwaran и Hell_Fox_X.

1. Аккаунт A → **Собрать коллаб** → дата, игра, 20:00–23:00 → **Найти участников**.
2. У свободной аккаунт B нажмите **Пригласить**, добавьте сообщение и отправьте.
3. Аккаунт B (в другом браузере или профиле браузера) → **Приглашения** → **Принять**.
4. У обоих теперь появится синий маркер в календаре, а при поиске на эти часы статус будет **Занята**.
5. Отмените принятый коллаб с одной стороны: маркер должен пропасть у обеих.

### 8. Проверить GitHub Pages, если адрес сайта отдаёт 404

Папка проекта опубликована в GitHub, но GitHub Pages **должен иметь корректный источник публикации**. Доступ к настройкам Pages есть у владельца репозитория:

1. Откройте **https://github.com/Gilbertum/streamerskaya/settings/pages**.
2. **Build and deployment → Source:** выберите **Deploy from a branch**.
3. **Branch:** `main`, **Folder:** `/(root)`, затем **Save**.
4. Дождитесь завершения процесса в **Actions / Pages build and deployment**.
5. Откройте **https://gilbertum.github.io/streamerskaya/collabs/**. Если показывается «Firebase ещё не подключён», публикация HTML успешна, осталось подключить Firebase.

**Внимание:** эти настройки описаны для существующего GitHub Pages в репозитории `streamerskaya`. Если у вас уже настроен Pages с другим способом публикации, не меняйте его наугад: в таком случае лучше выбрать отдельный репозиторий для Collab Room.

## Процесс работы

- Стримеры отмечают собственные планы.
- В поиске «свободна» = нет пересекающихся стримов, блокировок или принятых коллабов.
- «Под вопросом» = есть пересекающаяся жёлтая отметка; приглашение можно отправить.
- Ожидающий ответа запрос **не блокирует** время. Только статус «Принято» блокирует время у обоих.
- Время `20:00–02:00` означает ночь на **следующий** календарный день. Интервал `00:00–00:00` в форме отметки — ровно **24 часа**, без минутных пробелов.
- Все события, окна и поиск в версии 1.0 интерпретируются в **МСК (UTC+3)**. Переход летнего времени не поддерживается: его в Москве нет.

## Приватность

- `allowedUsers` — владелец настраивает в Firebase Console.
- `members` — ник, ссылки, типичное время; читают только допущенные участницы.
- `slots` — отметки занятости и названия стримов; читают только допущенные участницы. **Не пишите там личные причины отсутствия**: другие участницы увидят тип занятости.
- `proposals` — игра и сообщение; видны **только отправителю и получателю**.
- `collabLocks` — время, название игры и пара участников; видны допущенным участницам, чтобы поиск понимал занятость.
- `publicSchedules` — отдельная публичная копия **только отмеченных стримов**; доступна по прямому UID-ссылке без входа.
- Email, пароль и персональная причина отсутствия в публичных данных не хранятся.

## Известные ограничения MVP

- Это не полноценный Google Calendar: без двусторонней синхронизации с Twitch и внешними календарями.
- Уведомления **внутри сайта**, пока участница его открыла; нет push, email или сообщений в Telegram о новом приглашении.
- Принятые приглашения видны в закрытых календарях. Для показа зрителям добавьте отдельное публичное событие «Стрим» с игрой/коллабом.
- Поиск сделан для небольшого закрытого круга (около 5–20 человек). Он читает отметки участников в клиент. Для сотен участниц потребуется пагинация и серверная логика.
- Два одновременных принятия разных приглашений не защищены серверной блокировкой конфликтов: перед принятием выполняется проверка, но при одновременных действиях организатору нужно перепроверить пересечения.
- Нельзя редактировать полученные приглашения: можно принять/отклонить или запросить новое время.
- Из скриншотов **ничего не импортируется автоматически**. Исторические события можно занести вручную, если нужно.

## Troubleshooting

| Симптом | Что проверить |
| --- | --- |
| «Firebase ещё не подключён» | `collabs/firebase-config.js` всё ещё с `PASTE_...` |
| Invalid API key / auth invalid | Сверьте объект конфигурации с Firebase → Project settings → Your apps |
| Ошибка permissions / Missing or insufficient permissions | Firestore → Rules опубликованы? UID добавлен в `allowedUsers` с boolean `true`? |
| Email/пароль не подходят | Authentication → Sign-in method: Email/Password включен; пользователь реально создан |
| Отправка восстановления не работает | Почта указана корректно; проверьте Spam; Authentication → Templates |
| Сайт 404 | GitHub → Settings → Pages → источник `main` / `(root)`; проверьте Actions |
| У зрителей пустой календарь | Стрим должен быть помечен как публичный; проверьте профиль и нажмите «↻ Обновить» |
| Два человека спорят о времени | У обеих проверить личные блокировки, принятые коллабы и наличие совпадающих часов |
| Блокировка после полуночи | Записывайте стрим `20:00–02:00`, а не два отдельных события |

## Отключение участницы и резервное копирование

- Чтобы отозвать доступ, установите в `allowedUsers/{UID}` поле `enabled = false` (и при необходимости отключите аккаунт в Authentication). После обновления страницы бывшая участница не сможет читать приватные документы.
- Резервного копирования внутри приложения пока нет. Экспорт Firestore и автоматические резервные копии могут потребовать платного тарифа; храните важные договорённости также в собственном календаре.
- Для отката сайта можно **Revert** релизного Pull Request в GitHub; для полного удаления также удалите `collabs/` через отдельный PR. Данные в Firebase сами не удаляются.

**Документация:** https://firebase.google.com/docs/web/setup · https://firebase.google.com/docs/auth/web/password-auth · https://firebase.google.com/docs/firestore/security/get-started · https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

# Обновление 2.0: зрительская неделя и отдельный модераторский доступ

**Обязательное действие после релиза:** ещё раз откройте Firebase Console → Firestore Database → Rules, замените правила полным текстом из актуального файла collabs/firestore.rules и нажмите **Publish**. Без обновления правил новые функции не смогут читать или сохранять данные.

## Социальные сети в профиле

Личный кабинет → **Профиль**. Заполните по желанию Telegram, YouTube, TikTok и Discord. Формат ссылок — полный HTTPS-адрес. Не забывайте сохранить профиль.

На зрительской странице появятся кнопки только заполненных соцсетей, плюс Twitch, если он указан. Кнопки входа в комнату там больше нет. Steam доступен другим стримерам в поиске и при отправке приглашения, но не аудитории.

## Расписание для сообщества

- Тип **Стрим**: игра, день, время. Включите «Показать зрителям», когда событие можно раскрыть.
- Тип **Выходной**: новая отметка в календаре. При выборе автоматически устанавливаются 00:00–00:00 (весь день) и галочка публикации; при желании её можно снять.
- Типы **Недоступна**, **Под вопросом**, **Свободна** остаются закрытыми.

Публичное расписание открывается по старой зрительской ссылке, но теперь показывает **пять дней, понедельник–пятница**, с переключением недель. День без опубликованного события — **«Неизвестно»**, а не «Выходной».

Новые принятые коллабы отображаются в зрительском календаре только как **«Коллаба»** с временем. Игра, ник партнёра, личное сообщение не передаются в публичные маркеры. Подтверждённые коллабы версии 1.1 не получат маркеры задним числом; при необходимости пересоздайте приглашение и примите его заново.

**Секретные подробности нельзя вручную заносить в публичный стрим.** Если автор сам включил публичность для события с названием игры, зрители увидят это название.

## Отдельный доступ модераторов

Для каждого модератора:

1. Firebase → **Authentication → Users → Add user**. Создайте аккаунт модератора и скопируйте его UID.
2. В своём кабинете стримера → **Профиль** → **Ссылка для модераторов**, нажмите «Копировать».
3. Firebase → **Firestore Database → Data**. Создайте коллекцию с названием **moderatorAccess**.
4. Внутри коллекции создайте документ с **Document ID = UID стримера** (тот же UID, что в зрительской ссылке). Можно добавить произвольное поле label типа string для удобства.
5. В документе стримера создайте **подколлекцию users**.
6. В подколлекции users создайте **документ с ID = UID модератора**, добавьте поле **enabled** с типом **boolean**, значением **true**.
7. Отправьте модератору отдельную ссылку, полученную на шаге 2. Он входит со своей почтой и паролем Firebase.

Формат ссылки: **https://gilbertum.github.io/streamerskaya/collabs/#/mod/UID_СТРИМЕРА**.

Это не секретная ссылка в качестве пароля: даже если её переслать, доступ без авторизации и записи в moderatorAccess будет запрещён. Модератору не нужен документ в allowedUsers, если он не является одновременно участником-стримером.

Модератор видит **месячный календарь**, все запланированные события, закрытые статусы доступности, подтверждённые коллабы с названием игры и партнёром. Он не может редактировать события и не видит сообщения или неподтверждённые приглашения.

Чтобы отозвать доступ, установите enabled = **false** или удалите документ модератора из подколлекции users. Для другого стримера доступ выдаётся в отдельной ветке moderatorAccess с его UID.

## Проверка обновления

1. Войдите как стример, сохраните несколько соцсетей и добавьте один публичный выходной.
2. Откройте зрительскую ссылку в режиме инкогнито: должна появиться недельная доска и только заполненные соцсети, без кнопки входа.
3. Проверьте, что Steam отображается в модальном окне отправки приглашения.
4. Откройте модераторскую ссылку без входа: должен быть экран авторизации. Без документа разрешения — отказ.
5. Войдите модератором, которому выдали права: должна открыться сетка месяца без возможности редактирования.
6. Примите коллаб между двумя участницами: в приватном календаре должны отображаться игра и партнёр, а зрителям — обезличенная «Коллаба»; отмените и проверьте исчезновение публичного маркера.

**Не протестировано на реальной базе:** авторизация модераторов и записи коллабов до тех пор, пока в вашем Firebase не опубликованы новые правила и не созданы реальные аккаунты.

# Релиз 3.0: семь дней, быстрые действия, переносы и права модератора

## ВАЖНО: обновление Firebase Rules

После слияния релиза откройте [Firebase Console](https://console.firebase.google.com/) → Firestore Database → Rules.

1. Откройте файл [collabs/firestore.rules](https://github.com/Gilbertum/streamerskaya/blob/main/collabs/firestore.rules).
2. Скопируйте **весь файл** в редактор Firestore Rules и нажмите **Publish**.
3. **Не удаляйте Firestore и не создавайте базу заново**. Существующие профили, расписания и приглашения остаются на месте.
4. Новые типы данных при использовании создаются автоматически. Новых секретов, Cloud Functions и платного хостинга не требуется.

Важно: пока старые правила не обновлены, сохранение Telegram DM, примечаний, предложений и настроек коллабов может возвращать permission-denied. Обычная зрительская ссылка продолжает отображать ранее опубликованные стримы.

## Для стримеров: расписание и выходные

- Новые события **Стрим** и **Выходной** теперь **публикуются автоматически** при сохранении, если не поставить галочку **«Не показывать зрителям»**.
- Ранее сохранённые скрытые события остаются скрытыми. Чтобы показать их, откройте событие, снимите галочку и сохраните.
- Публичная ссылка теперь показывает **все 7 дней** недели: понедельник–воскресенье. Неизвестные планы по-прежнему помечаются «Неизвестно».
- У каждого личного события в календаре есть отдельные кнопки **Изменить** и **Удалить**. Удаление требует подтверждения.
- Для стримов можно добавить **примечание** (до 500 символов). Оно видно только авторизованным участницам и модераторам, но не зрителям.

## Управление подтверждённой коллабой

Откройте личный календарь, выберите день с подтверждённым коллабом. Рядом с коллабом есть три кнопки:

- **Зрителям:** независимо от второго участника включите/выключите раскрытие **названия игры** и **ника партнёра** на своей публичной странице. По умолчанию оба поля скрыты. Согласовывайте раскрытие данных с партнёром!
- **Перенести:** предложите другую дату, время или игру. **Старый коллаб остаётся подтверждённым**, пока второй участник не примет перенос. Если отклонит — старое время не изменится. Если примет — исходный слот освобождается, новый подтверждается у обоих.
- **Отменить:** отменяет подтверждённую коллабу у обоих участников, снимает занятость и удаляет её публичные карточки.

Предложение переноса отображается в разделе **Приглашения** как «↪ Перенос». Вторая участница должна **принять** либо **отклонить** предложение, как обычное приглашение. Если старая коллаба была уже отменена, новое согласование недействительно.

На публичной странице «Коллаба» всегда отображается с датой и временем; название игры и ник другого участника появляются только при явном выборе автора своего канала.

**Ограничения:** автоматическая публичная карточка старого коллаба версии 1.1 может отсутствовать. Кнопка «Зрителям» позволяет создать карточку для своего расписания, если коллаб всё ещё подтверждён. При одновременных конкурирующих подтверждениях двух разных предложений возможны конфликты; для масштабного проекта потребуется серверное управление бронированием.

## Для модераторов: каналы и подробности

1. Откройте ссылку своего первого канала **/#/mod/UID_СТРИМЕРА**, войдите как модератор. Доступ по-прежнему выдаётся через moderatorAccess / UID стримера / users / UID модератора с boolean-полем enabled = true.
2. Для другого канала попросите его отдельную модераторскую ссылку. Откройте её или нажмите **+ Добавить канал** и вставьте ссылку или UID.
3. Возвращайтесь к предыдущим каналам через переключатель **Твои каналы** в шапке страницы. В список попадают только ссылки, уже посещённые в данном браузере, доступ к которым Firebase подтвердил; сохранение происходит локально в браузере. При открытии с другого устройства ссылки понадобится добавить снова.
4. В календаре месяца нажмите цветную плашку стрима, выходного, подтверждённого или ожидающего коллаба. Откроются подробности: название игры, время по МСК, внутренние примечания, а у коллабов — участник и статус.
5. Под календарём остаётся только **Коллабы месяца**: отдельно подтверждённые и ожидающие ответа. Общий список «События месяца» удалён.

**Безопасность:** модераторы **не имеют доступа к текстам сообщений приглашений**. Для ожидающих предложений создаётся отдельная внутренняя карточка (дата, время, игра, участники, без сообщения) в коллекции moderatorPending. Только авторизованный модератор соответствующего канала может её читать. После принятия/отказа/отмены эта карточка удаляется.

**Исторические данные:** старые ожидающие предложения, созданные до версии 3.0, не имеют таких карточек. Они продолжают работать в разделе «Приглашения», но модератор увидит их в колонке «Ожидают ответа» только если предложение будет создано заново.

## Личный Telegram для быстрой связи

1. В личном кабинете откройте **Профиль**.
2. В поле **Личный Telegram для связи со стримерами** вставьте ссылку на личный профиль, например https://t.me/your_username.
3. Нажмите **Сохранить профиль**.
4. Участницы увидят кнопку **✉ Написать в Telegram** рядом с Twitch/Steam в поиске и в окне приглашения.

**Разница полей:** «Telegram» в разделе соцсетей — публичная ссылка для зрителей на канал/группу; «Личный Telegram» — ссылка для участниц. Она **не копируется** в зрительскую коллекцию publicSchedules. Не вводите в поле номер телефона, если хотите сохранить его приватным.

## Тест после обновления

1. Сохраните профиль с новым личным Telegram. У второй участницы должна появиться кнопка прямого сообщения.
2. Добавьте стрим без галочки: он должен появиться у чата без дополнительных действий.
3. Поставьте «Не показывать зрителям», сохраните — событие исчезнет из зрительского расписания.
4. Проверьте 7-дневную публичную неделю, включая субботу и воскресенье.
5. Примите новую коллабу, откройте «Зрителям», включите раскрытие игры, проверьте её публичную карточку.
6. Предложите перенос и убедитесь, что **до согласия** старая коллаба не исчезла. Примите из второго аккаунта, проверьте оба календаря.
7. Проверьте отмену с каждой стороны на отдельных тестовых коллабах.
8. Войдите разрешённым модератором, откройте подробности стрима, убедитесь, что предложения подсвечиваются, но сообщений нет.
9. Добавьте вторую модераторскую ссылку, попробуйте переключить канал; без прав на другой канал должен быть отказ.

**Проверки кода не заменяют проверку в вашем Firebase.** Права и транзакции требуют интеграционного теста с реальными разрешёнными аккаунтами после публикации актуальных правил.

# Collab Room 4.0 — понятные ячейки, «Хочу коллабу» и Twitch-панель

## 1. Что изменилось в календаре

В календаре вместо «1 событий» теперь показываются короткие подписи: **Стрим**, **Выходной**, **Коллаба**. Можно увидеть до трёх событий в ячейке, дополнительные показываются счётчиком +N. При наведении на стрим/коллаб видны названия; для подробностей по-прежнему нужно нажать на дату.

В меню **Новое событие** остаются **Стрим**, **Выходной** и переход в специальную форму **✦ Хочу коллабу**. Старые отметки недоступности и «Под вопросом» автоматически НЕ удаляются из Firestore: их можно видеть в календаре и удалить вручную, если они больше не нужны.

## 2. «Хочу коллабу»: несколько вариантов и несколько стримеров

- В своём календаре нажмите **✦ Хочу коллабу**, либо **+ Добавить событие → Хочу коллабу**.
- Укажите **игру** и **1–5 вариантов** даты/времени по Москве.
- Отметьте галочками стримеров (до 10 одновременно). Участники без заполненной ссылки Twitch тоже доступны для приглашения, если у них есть кабинет в Collab Room.
- Добавьте необязательное сообщение и нажмите **Отправить приглашения**.
- Каждому выбранному человеку придёт **один запрос со списком вариантов**, а не отдельная заявка на каждую дату.
- Получатель откроет вкладку **Приглашения**, выберет нужный слот в выпадающем списке и нажмёт **Принять** либо **Отклонить**.
- После принятия выбранная дата и время блокируются в календарях обоих участников. Другие предложенные варианты не блокируются.
- Если какой-то получатель уже занят во всех вариантах или база отказала в записи, сайт сообщит, кому заявка отправлена, а кому — нет.

**Важно:** для этих полей нужны новые правила Firebase. После выпуска релиза откройте Firebase → Firestore Database → Rules, полностью вставьте файл collabs/firestore.rules из main и нажмите Publish. Старые однослотовые приглашения продолжат работать.

## 3. Twitch-панель участников: безопасное подключение без платного сервера

Панель показывает только тех стримеров, кто указал ссылку Twitch в профиле Collab Room. Она находится над личным календарём. Там есть ник, аватарка Twitch, подтверждённый статус онлайн/оффлайн и кнопка **Смотреть трансляцию** (если Twitch действительно сообщает, что канал в эфире).

Для статуса и аватарки используется **официальный Twitch Helix API**: Get Users и Get Streams. Обычные ссылки без API не позволяют безопасно и достоверно определить онлайн-статус.

**Однократная настройка разработческого приложения Twitch владельцем сайта:**

1. Откройте [Twitch Developer Console](https://dev.twitch.tv/console/apps). Войдите в свой Twitch-аккаунт. Для регистрации приложения Twitch может потребовать подтверждённую почту и двухфакторную аутентификацию.
2. Создайте приложение (Register Your Application). Название, например, Collab Room.
3. В **OAuth Redirect URLs** добавьте **точно** этот URL:
   **https://gilbertum.github.io/streamerskaya/collabs/twitch-callback.html**
4. Тип приложения: **Public Client**, если Twitch предлагает выбор Public/Confidential. Категория — подходящая для веб-приложения (например, Website Integration), в зависимости от текущего интерфейса Twitch.
5. Скопируйте **Client ID** приложения. Это публичный идентификатор, не пароль.
6. Откройте в GitHub [collabs/firebase-config.js](https://github.com/Gilbertum/streamerskaya/blob/main/collabs/firebase-config.js), нажмите Edit и поменяйте только одну строку:
   `export const twitchClientId = "";`
   на:
   `export const twitchClientId = "ВАШ_CLIENT_ID";`
7. Commit changes в main (можно через отдельную ветку и pull request). Дождитесь завершения GitHub Pages.

**Не добавляйте в репозиторий Twitch Client Secret, OAuth Access Token, Refresh Token или другие приватные ключи.** Они не нужны для этого браузерного способа. Firebase-конфигурацию не меняйте.

**Для каждой участницы, которая хочет видеть статус:**

1. Откройте личный календарь, нажмите **Подключить Twitch** на панели.
2. Twitch попросит войти и подтвердить авторизацию (личные данные с дополнительными правами приложение не запрашивает).
3. После возврата на сайт откроется панель с актуальными аватарками и статусом стримеров.
4. Обновление происходит при открытии календаря, вручную по кнопке **↻ Проверить** и примерно каждые 2 минуты, пока календарь открыт.
5. Доступ Twitch хранится **только в sessionStorage текущей вкладки браузера**, не в GitHub и не в Firestore. Если вкладку закрыть или Twitch-токен истечёт, подключение потребуется повторить.

До настройки Client ID или подключения Twitch панель показывает участников и ссылки на каналы с пометкой **«Статус не проверен»** — нельзя считать непроверенный канал оффлайном. Кнопка **Смотреть трансляцию** появляется только при подтверждённом статусе «В эфире», иначе есть **Открыть канал**.

Twitch может показывать данные с небольшой задержкой. Сайт не обещает покадровый real-time статус.

Источники для настройки:
- https://dev.twitch.tv/docs/authentication/register-app
- https://dev.twitch.tv/docs/authentication/getting-tokens-oauth
- https://dev.twitch.tv/docs/api/reference/users
- https://dev.twitch.tv/docs/api/reference/streams

## 4. Тест после обновления

1. Откройте календарь: вместо счётчиков событий должны быть текстовые типы.
2. Откройте добавление события: старых вариантов «Не могу коллабиться», «Под вопросом» и «Точно свободна» в новых событиях нет.
3. Выберите «Хочу коллабу», введите два разных окна и двух стримеров, отправьте.
4. На втором аккаунте проверьте приглашение, переключите предложенное время и примите. У обеих участниц должен появиться коллаб на **выбранную**, а не первую дату.
5. Проверьте, что старая система обычного приглашения и переноса работает.
6. После настройки Twitch Client ID подключите Twitch и убедитесь, что аватарки и статусы совпадают с самими каналами; проверить это можно и по аккаунту, который сейчас в эфире.
7. Выйдите из Twitch-сессии или закройте вкладку: панель не должна вводить зрителя в заблуждение выдуманным «Оффлайн».

Ограничения: в одном массовом отправлении максимум 10 адресатов и 5 окон; каждый пользователь выбирает один вариант независимо. Если несколько участников выберут один вариант, это отдельные двусторонние коллабы и потенциальное пересечение времени — проверка занятости работает на момент принятия, но для полного предотвращения гонок нужен серверный транзакционный механизм. Этот MVP рассчитан на небольшой круг стримеров.

# Collab Room 5.0 — раздел «Стримеры», групповое согласование, Twitch OAuth

## 1. Обновите Firestore Rules в Firebase

После публикации релиза откройте Firebase Console → Firestore Database → Rules. Скопируйте **весь** актуальный файл из https://github.com/Gilbertum/streamerskaya/blob/main/collabs/firestore.rules и нажмите **Publish**.

Это обновление разрешает новые закрытые коллекции groupWishes, groupDiary, groupCalendar и публичную publicGroupCollabs. Все прежние профили, события и личные приглашения остаются на месте. **Не создавайте базу заново, не удаляйте старые коллекции, не включайте открытые правила.** До обновления Rules новые действия могут возвращать permission-denied.

## 2. Новая вкладка «Стримеры»

После «Профиля» расположена самостоятельная вкладка «Стримеры». Старая панель «Кто сейчас на Twitch» перенесена туда. Ниже — карточки участниц с Twitch, прошедшим проверку статусом, и ссылкой на подробности.

Нажмите карточку участницы: появятся все её заполненные ссылки (Twitch, Steam, Telegram, личный Telegram, YouTube, TikTok, Discord), обычные часы и календарь на месяц. Можно переключать месяцы и открывать день с деталями события. Другие участницы могут смотреть события, но не редактировать их. Вкладка скрыта от зрителей — её видят только авторизованные участницы Collab Room.

## 3. Новое групповое согласование коллабов

1. Организатор открывает **«Хочу коллабу»**, выбирает игру, до 5 вариантов даты/времени и до 10 участниц.
2. В **«Приглашениях»** появляется одна групповая заявка. Каждая приглашённая отмечает **все подходящие** ей варианты галочками и нажимает **«Отправить выбранные варианты»**.
3. Организатор видит ответы каждой участницы. Сайт вычисляет пересечение выбранных вариантов.
4. Организатор выбирает **один из общих** вариантов и нажимает **«Подтвердить для всех»**. До этого момента время ни у кого не блокируется.
5. После подтверждения выбранное время появится в календарях организатора и всех приглашённых. Зрителям оно показывается как **«Коллаба»** без имён и названия игры.
6. Если общего времени нет, подтверждение недоступно — нужно предложить новые даты. Любая участница может отменить групповую коллабу с подтверждением, и она исчезнет из календарей всех.

Все часы указаны по МСК. Старые личные приглашения продолжают работать как раньше — миграция их данных не требуется. Модераторские календари показывают новые групповые события без текста личных сообщений.

**Ограничение:** клиент проверяет занятость всех участников перед финальным решением, но одновременное подтверждение двух разных коллабов на разных устройствах теоретически может создать пересечение. Для строгой блокировки гонок требуется серверная транзакционная координация.

## 4. Twitch: исправление ошибки подключения

Предыдущая страница callback не объясняла, почему не был принят OAuth-ответ. Новая версия:

- Показывает ошибку Twitch, даже если она передана в URL как query, а не fragment.
- При отсутствии необязательного expires_in не отклоняет токен автоматически; использует ограниченный срок и проверяет его через официальный Twitch /validate.
- Восстанавливает OAuth state из одноразовой записи при потере sessionStorage. В localStorage сохраняется **только короткоживущий state**, не access token. Access token остаётся только в sessionStorage текущей вкладки.
- Показывает точную причину при несовпадении state или отсутствии access_token.

В Twitch Developer Console проверьте, что URL не только введён, но **добавлен** кнопкой «Добавить» и **сохранён**. Адрес должен совпадать посимвольно:

https://gilbertum.github.io/streamerskaya/collabs/twitch-callback.html

Тип — Public Client. Client ID должен совпадать с публичным twitchClientId в firebase-config.js. **Client Secret никуда на GitHub не добавлять!** Подключайте Twitch только кнопкой во вкладке «Стримеры» в той же вкладке браузера.

Официальная документация: https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/ и https://dev.twitch.tv/docs/authentication/register-app/

## 5. Проверка после обновления

1. Сначала опубликуйте новые Firestore Rules.
2. Откройте «Стримеры», посмотрите профиль другой участницы и нажмите день в её месячном календаре.
3. Создайте групповую заявку с двумя датами на двух участниц.
4. Пусть первая выберет обе даты, вторая только вторую.
5. Организатор должен видеть только **вторую** как общую. Подтвердите её и проверьте три календаря.
6. Проверьте зрительское расписание (отображается только обезличенная «Коллаба») и модераторский календарь.
7. Отмените группу и убедитесь, что событие исчезло у всех.
8. Подключите Twitch и проверьте аватары/статус. Если останется ошибка, пришлите новый текст с callback-страницы — без секретов.

Реальную авторизацию и Firebase-права требуется проверить на пользовательских аккаунтах после публикации правил.

# Исправление 5.0.1: конфликты приглашений и жёлтые коллабы

## Почему приглашение не принималось

Ранее приложение показывало только общее «На новом времени есть занятость». Оно проверяет **обоих участников**: если у организатора или получателя уже есть стрим, выходной, подтверждённая коллаба или групповая бронь, пересекающаяся с предложенным временем, второе приглашение **не подтверждается**, чтобы избежать двойного бронирования.

Теперь интерфейс показывает **имя занятого участника, название события, дату и часы**. Предупреждение видно прямо во входящем приглашении, ещё до нажатия «Принять», и после попытки принятия. Данные и права не изменены.

Если новое приглашение совпадает с уже подтверждённой коллабой по двум участникам, игре и точному интервалу, оно помечается **«Повтор»**. Получатель может нажать **«Убрать повтор»** — это отклоняет только дублирующее приглашение, а существующая подтверждённая коллаба сохраняется.

У каждого приглашения теперь показываются последние шесть символов ID («№ ...»), чтобы сравнить два скриншота и убедиться, что оба пользователя говорят именно об одном запросе. **Не путайте два разных приглашения, даже если у них совпадают игра и часы.**

Если в эти часы организатор уже играет с одной участницей и хочет добавить остальных, **не создавайте несколько независимых двухсторонних броней на одно время**. Используйте общий процесс «Хочу коллабу» с несколькими участницами — он подтверждает единое время для всей команды. Для уже принятых отдельных броней потребуется согласовать переход и вручную отменить прежнюю бронь, чтобы не было конфликта.

## Жёлтые коллабы

Все подтверждённые коллабы теперь **тёпло-жёлтые** (ярлык внутри личного месяца, плашка деталей, месячный календарь стримера и модератора, недельная доска зрителей). Стримы остаются розовыми, выходные — серо-синими. Текст подсказки в личном календаре обновлён.

## Проверка после релиза

1. Обновите оба открытых окна сайта через Ctrl+F5.
2. Если приглашение всё ещё ожидает ответа, откройте его в аккаунте получателя — появится конкретная причина конфликта и сокращённый номер запроса.
3. Сравните номер заявки у отправителя и получателя. Если отличаются — это разные приглашения.
4. Если одна из броней уже подтверждена, проверьте её дату, время и участников в календарях, прежде чем отклонять дубликат.
5. Для занятого времени согласуйте другой интервал с организатором или создайте новую групповую заявку.

**Правила Firebase менять не требуется**: исправление использует уже доступные данные личных календарей и не вводит новых коллекций или полей.

# Collab Room 6.0 — несколько приглашений в одну команду

## Что исправлено

Ситуация: Xwaran отправляет отдельные приглашения Reus, Hell_Fox_X и PsPuer на **Chained Together, 21 ноября, 15:00–00:00 МСК**. Раньше после ответа Reus сайт ошибочно блокировал принятие оставшихся приглашений, поскольку считал уже занятого организатора конфликтом.

Теперь, если **один организатор** приглашает разных людей на **ту же игру, дату и точно те же часы**, существующее подтверждение **не препятствует** следующему подтверждению. Все остальные конфликты с другими играми, чужими коллабами, выходными, стримами и изменённым временем продолжают блокироваться.

- Каждая заявка сохраняется в прежнем формате: личное приглашение и собственная подтверждённая блокировка. Старые записи не меняются.
- Принятые блокировки того же организатора, игры и окна автоматически объединяются в одно событие в закрытых календарях.
- Когда принимает Reus, видно Xwaran + Reus; когда принимает Hell_Fox_X, состав обновляется до трёх; после PsPuer — до четырёх.
- На дату выводится **одна** коллаба. Кнопка **«Участники и управление»** показывает подтверждённый состав. У организатора — отдельные кнопки переноса, отмены участия и настроек показа зрителям для каждой приглашённой. Приглашённая может управлять только собственным участием.
- Во вкладке «Приглашения» и в месячном календаре «Стримеры» состав обновляется по мере подтверждений. Модераторы организатора увидят объединённое событие.
- На публичной неделе одинаковые карточки одного временного интервала объединяются. **Новые имена никогда не раскрываются автоматически**: сохраняются ранее установленные индивидуальные настройки публичности.

## Как проверить

1. Обновить браузер (Ctrl+F5) у Xwaran, Reus и остальных.
2. Hell_Fox_X принимает уже отправленное приглашение на 21 ноября, 15:00–00:00. Проверить, что Reus и Xwaran видят дополненный состав команды.
3. PsPuer принимает своё приглашение. Проверить, что у всех четырёх людей видны Xwaran, Reus, Hell_Fox_X и PsPuer.
4. Открыть 21 ноября → «Участники и управление». Проверить, что перенос/отмена одного человека не уничтожает остальные подтверждения.
5. Проверить месячный календарь «Стримеры» и публичную неделю.
6. На отдельном тестовом мероприятии попробовать пересекающуюся **другую** игру или **другое** время — конфликт должен по-прежнему блокировать принятие.

**Firestore Rules обновлять не требуется:** схему документов, коллекции и права не меняли. Уже отправленные ожидающие приглашения продолжат работать с новой проверкой.

**Ограничение:** это динамическое объединение одинаковых отдельных приглашений, не новая серверная система транзакционной блокировки времени. Одновременные конкурентные операции в разных браузерах могут создавать гонки; для строгой защиты потребуется отдельная серверная координация. Групповой сценарий «Хочу коллабу» с выбором разных вариантов времени продолжает работать независимо.

## Исправление отображения: два события вместо одной общей коллабы

Если у одного стримера на 21 ноября отображаются **две** коллабы с кнопками «Зрителям / Перенести / Отменить», а у другого **одно** событие с кнопкой «Участники и управление», причина — **разные закешированные версии JavaScript**, а не обязательно две отдельные коллабы в базе.

В версии 6.0 несколько подтверждённых личных приглашений одного организатора на одни игру/день/часы объединяются на экране в одно событие. Старая версия кода рисовала каждую запись отдельно.

**Изменения кеширования:** входная HTML-страница теперь загружает основное приложение и таблицу стилей с новым параметром при каждом открытии/обновлении. Приложение передаёт тот же параметр всем локальным JS-модулям, включая состав команд, календарь и панель Twitch. Это не требует изменения Firebase или очистки чужих аккаунтов.

**Как проверить:**
1. Один раз обновить страницу сочетанием Ctrl+F5 (или открыть страницу в новой приватной вкладке), чтобы браузер получил новый HTML-загрузчик.
2. Дальше обычные обновления страницы должны подхватывать свежие модули автоматически, без очистки данных Firestore и браузера.
3. Открыть личный календарь → 21 ноября. Вместо двух строк должна отображаться **одна «Коллаба: Chained Together»**, состав: Xwaran, Reus, Hell_Fox_X (и PsPuer, если она уже подтвердила).
4. Если по-прежнему две строки, скопировать адрес страницы и проверить, что открыт именно https://gilbertum.github.io/streamerskaya/collabs/ . Не отменять подтверждённые приглашения только из-за визуального дублирования.

На GitHub Pages старый HTML некоторое время может оставаться в кеше; **первое принудительное обновление после этого исправления всё ещё рекомендуется**. После загрузки нового HTML кодовые модули загружаются с новым адресом при каждом обновлении.
