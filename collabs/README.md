# Collab Room — планировщик коллабораций

**Версия 1.0 (MVP).** Отдельный проект в папке `collabs/` репозитория `Gilbertum/streamerskaya`. Корневой сайт `streamerskaya` не меняется.

Предполагаемый адрес GitHub Pages (если Pages публикует ветку main, корень /root):
**https://gilbertum.github.io/streamerskaya/collabs/**

## Что работает

- Вход по email/паролю через Firebase Authentication. **Публичной регистрации нет.**
- Допуск по `allowedUsers/{UID}`: только одобренные участницы видят закрытые данные.
- Личные профили: ник, Twitch, Steam, обычные часы по будням и выходным.
- Календарь: стрим, «не могу», «под вопросом», «точно свободна». Без отметки день/время считается свободным.
- События `20:00–02:00` правильно блокируют вечер и следующий день до 02:00.
- Поиск свободных участниц по игре, дате и часам МСК; кандидаты сортируются на свободных / под вопросом / занятых.
- Приглашения: предложить → принять/отклонить → при принятии блокируется окно **у обеих**. Участницы могут отменить уже принятый коллаб.
- Живые обновления календаря и предложений при открытом сайте.
- Персональные зрительские ссылки `#/s/UID`: **только отмеченные как публичные стримы**, без внутренних расписаний, статусов и переписки.

## Firebase: полная инструкция для владельца (без программирования)

### 1. Создать проект

1. Откройте **https://console.firebase.google.com/** и войдите в Google-аккаунт владельца.
2. Нажмите **Create a project / Создать проект**. Например, `xwaran-collab-room`.
3. Google Analytics для этой маленькой программы можно **отключить**.
4. В настройках проекта **Project settings / Настройки проекта** найдите **Your apps / Ваши приложения**, нажмите значок **Web (</>)** и зарегистрируйте приложение `Collab Room`.
5. Скопируйте объект `firebaseConfig`: `apiKey`, `authDomain`, `projectId`, `storageBucket`, `messagingSenderId`, `appId`. Это публичная конфигурация веб-приложения, **не секретный пароль**.

### 2. Подключить Firebase Authentication

1. В меню Firebase откройте **Authentication** (в некоторых версиях интерфейса: **Build / Authentication**, либо **Security / Authentication**).
2. Нажмите **Get started / Начать**.
3. Вкладка **Sign-in method / Способы входа** → **Email/Password** → **Enable / Включить** → Save.
4. Проверьте **Settings / Настройки → Authorized domains / Авторизованные домены**. Добавьте `gilbertum.github.io`, если его там нет. Вводите домен **без** `https://`, без слэша и без `/streamerskaya/collabs/`.

### 3. Создать Cloud Firestore (не Realtime Database)

1. Firebase → **Firestore Database** → **Create database / Создать базу данных**.
2. Выберите **Standard edition** и **Native mode**, если консоль спрашивает; используйте основную базу `(default)`.
3. Выберите регион. Желательно европейский, доступный вашему проекту; впоследствии перенос региона потребует миграции.
4. Выберите **Start in production mode / Рабочий режим** (закрытые правила по умолчанию).
5. Откройте вкладку **Rules / Правила**.
6. Откройте на GitHub файл **`collabs/firestore.rules`**, скопируйте **весь** текст от `rules_version = '2';` до последней `}`.
7. Замените им содержимое редактора в Firebase → **Publish / Опубликовать**. Без этого шага сайт не сможет читать и записывать данные.

**Важно:** не используйте правила `allow read, write: if true;` и не выбирайте тестовый режим на постоянной основе. Публичные ссылки работают через отдельную коллекцию `publicSchedules`, а не через открытие всей базы.

### 4. Внести настройки Firebase в опубликованный сайт

1. Откройте **https://github.com/Gilbertum/streamerskaya/blob/main/collabs/firebase-config.js**.
2. Нажмите значок карандаша **Edit this file** (при необходимости: `...` → `Edit file`).
3. Внутри `export const firebaseConfig = { ... }` замените **все** шаблонные значения `PASTE_...` значениями объекта, который Firebase дал на шаге 1. Не удаляйте `export const firebaseConfig =`.
4. Нажмите **Commit changes** → сохраните в основную ветку `main`. Можно через отдельную ветку + Pull Request, если хочется оставить историю релизов.
5. Откройте сайт через несколько минут и обновите страницу с зажатой клавишей Ctrl (Ctrl+F5). Вместо «Firebase ещё не подключён» появится форма входа.

**Никогда не вставляйте** в этот файл сервисный ключ `private_key`, JSON из **Service accounts**, пароли, токены Twitch и ключи админ-доступа. `firebaseConfig` из настройки Web app, наоборот, рассчитан на использование в браузере.

### 5. Добавить аккаунты для каждой стримерши

Самый простой приватный способ — создать аккаунты **вручную**, без формы открытой регистрации.

Для **каждой** участницы, включая себя:

1. Firebase → **Authentication → Users / Пользователи** → **Add user / Добавить пользователя**.
2. Укажите её **email** и длинный случайный временный пароль. Не публикуйте пароль. Пользователь сможет установить свой через восстановление.
3. После создания скопируйте поле **UID** (длинный уникальный идентификатор пользователя).
4. Firebase → **Firestore Database → Data / Данные** → **Start collection / Создать коллекцию**.
   - Collection ID: `allowedUsers` (строго такое написание).
   - Document ID: вставьте **UID** из Authentication (не ник и не email).
   - Поле: **`enabled`**, тип **boolean**, значение **true** (именно логическое true, не строка `"true"`).
   - Сохраните.
5. Следующую участницу добавляйте в **ту же** коллекцию `allowedUsers` через **Add document**, каждый раз с её собственным UID.

**Как впервые войти участнице:** откройте сайт, введите **свою почту** в форме входа, нажмите **Восстановить пароль**, затем перейдите по письму Firebase и установите свой собственный пароль. После этого войдите на сайт с новым паролем.

**Если на экране «Аккаунт ещё не допущен»**, означает, что Authentication работает, но в Firestore нет документа `allowedUsers/{UID}` с `enabled = true`. UID будет написан на экране: сверьте его с Firestore.

### 6. Настроить профиль и дать ссылку своему чату

1. После входа откройте **Профиль**.
2. Заполните ник, Twitch, Steam, желаемые часы стримов по будням / выходным (МСК).
3. Нажмите **Сохранить профиль**.
4. На экране профиля скопируйте индивидуальную ссылку **«Ссылка для зрителей»**.
5. В **Расписание → + Добавить событие** укажите тип **Стрим**, игру, дату и часы, поставьте галочку **Показать зрителям**.
6. Сохраните и проверьте ссылку в браузере **инкогнито**: должны быть видны только публичные стримы. Типы «не могу», «под вопросом», приглашения и другие участницы не должны отображаться.

### 7. Проверить коллабы от начала до конца

Понадобятся две разные учётные записи из разрешённого списка, например Xwaran и Hell_Fox_X.

1. Аккаунт A → **Собрать коллаб** → дата, игра, 20:00–23:00 → **Найти участников**.
2. У свободной аккаунт B нажмите **Пригласить**, добавьте сообщение и отправьте.
3. Аккаунт B (в другом браузере или профиле браузера) → **Приглашения** → **Принять**.
4. У обоих теперь появится синий маркер в календаре, а при поиске на эти часы статус будет **Занята**.
5. Отмените принятый коллаб с одной стороны: маркер должен пропасть у обеих.

### 8. Проверить GitHub Pages, если адрес сайта отдаёт 404

Папка проекта опубликована в GitHub, но GitHub Pages **должен иметь корректный источник публикации**. Доступ к настройкам Pages есть у владельца репозитория:

1. Откройте **https://github.com/Gilbertum/streamerskaya/settings/pages**.
2. **Build and deployment → Source:** выберите **Deploy from a branch**.
3. **Branch:** `main`, **Folder:** `/(root)`, затем **Save**.
4. Дождитесь завершения процесса в **Actions / Pages build and deployment**.
5. Откройте **https://gilbertum.github.io/streamerskaya/collabs/**. Если показывается «Firebase ещё не подключён», публикация HTML успешна, осталось подключить Firebase.

**Внимание:** эти настройки описаны для существующего GitHub Pages в репозитории `streamerskaya`. Если у вас уже настроен Pages с другим способом публикации, не меняйте его наугад: в таком случае лучше выбрать отдельный репозиторий для Collab Room.

## Процесс работы

- Стримеры отмечают собственные планы.
- В поиске «свободна» = нет пересекающихся стримов, блокировок или принятых коллабов.
- «Под вопросом» = есть пересекающаяся жёлтая отметка; приглашение можно отправить.
- Ожидающий ответа запрос **не блокирует** время. Только статус «Принято» блокирует время у обоих.
- Время `20:00–02:00` означает ночь на **следующий** календарный день.
- Все события, окна и поиск в версии 1.0 интерпретируются в **МСК (UTC+3)**. Переход летнего времени не поддерживается: его в Москве нет.

## Приватность

- `allowedUsers` — владелец настраивает в Firebase Console.
- `members` — ник, ссылки, типичное время; читают только допущенные участницы.
- `slots` — отметки занятости и названия стримов; читают только допущенные участницы. **Не пишите там личные причины отсутствия**: другие участницы увидят тип занятости.
- `proposals` — игра и сообщение; видны **только отправителю и получателю**.
- `collabLocks` — время, название игры и пара участников; видны допущенным участницам, чтобы поиск понимал занятость.
- `publicSchedules` — отдельная публичная копия **только отмеченных стримов**; доступна по прямому UID-ссылке без входа.
- Email, пароль и персональная причина отсутствия в публичных данных не хранятся.

## Известные ограничения MVP

- Это не полноценный Google Calendar: без двусторонней синхронизации с Twitch и внешними календарями.
- Уведомления **внутри сайта**, пока участница его открыла; нет push, email или сообщений в Telegram о новом приглашении.
- Принятые приглашения видны в закрытых календарях. Для показа зрителям добавьте отдельное публичное событие «Стрим» с игрой/коллабом.
- Поиск сделан для небольшого закрытого круга (около 5–20 человек). Он читает отметки участников в клиент. Для сотен участниц потребуется пагинация и серверная логика.
- Два одновременных принятия разных приглашений не защищены серверной блокировкой конфликтов: перед принятием выполняется проверка, но при одновременных действиях организатору нужно перепроверить пересечения.
- Нельзя редактировать полученные приглашения: можно принять/отклонить или запросить новое время.
- Из скриншотов **ничего не импортируется автоматически**. Исторические события можно занести вручную, если нужно.

## Troubleshooting

| Симптом | Что проверить |
| --- | --- |
| «Firebase ещё не подключён» | `collabs/firebase-config.js` всё ещё с `PASTE_...` |
| Invalid API key / auth invalid | Сверьте объект конфигурации с Firebase → Project settings → Your apps |
| Ошибка permissions / Missing or insufficient permissions | Firestore → Rules опубликованы? UID добавлен в `allowedUsers` с boolean `true`? |
| Email/пароль не подходят | Authentication → Sign-in method: Email/Password включен; пользователь реально создан |
| Отправка восстановления не работает | Почта указана корректно; проверьте Spam; Authentication → Templates |
| Сайт 404 | GitHub → Settings → Pages → источник `main` / `(root)`; проверьте Actions |
| У зрителей пустой календарь | Стрим должен быть помечен как публичный; проверьте профиль и нажмите «↻ Обновить» |
| Два человека спорят о времени | У обеих проверить личные блокировки, принятые коллабы и наличие совпадающих часов |
| Блокировка после полуночи | Записывайте стрим `20:00–02:00`, а не два отдельных события |

## Отключение участницы и резервное копирование

- Чтобы отозвать доступ, установите в `allowedUsers/{UID}` поле `enabled = false` (и при необходимости отключите аккаунт в Authentication). После обновления страницы бывшая участница не сможет читать приватные документы.
- Резервного копирования внутри приложения пока нет. Экспорт Firestore и автоматические резервные копии могут потребовать платного тарифа; храните важные договорённости также в собственном календаре.
- Для отката сайта можно **Revert** релизного Pull Request в GitHub; для полного удаления также удалите `collabs/` через отдельный PR. Данные в Firebase сами не удаляются.
